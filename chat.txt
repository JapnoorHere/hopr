Termius is an SSH client with a terminal, host vault, SFTP, port forwarding, snippets, and sync. Here's the stack I'd pick for "lightweight, fast, good UI":

Recommended: Tauri 2 + Rust + React/Svelte

Shell: Tauri 2

Uses the OS webview, so installs are ~5-10 MB and idle RAM is a fraction of Electron's (which bundles Chromium, ~150 MB+ idle).
Rust backend gives you native performance and safe handling of credentials and sockets.
Tauri 2 also supports mobile (iOS/Android) if you ever want a Termius-style mobile app.

SSH/SFTP: russh + russh-sftp (Rust)

Pure Rust, async (tokio), no libssh2/OpenSSL linking pain.
Supports port forwarding, agent forwarding, keys, jump hosts.
Alternative: ssh2 crate (libssh2 bindings) is more battle-tested but synchronous and harder to cross-compile.

Terminal: xterm.js

The standard (VS Code uses it). Use the WebGL addon for fast rendering, plus the fit, search, unicode11, and web-links addons.
Wire it to Rust via Tauri events/channels: PTY data flows as binary chunks, not JSON strings, for speed.

Frontend: Svelte 5 or SolidJS (or React if you know it best)

Svelte/Solid compile to tiny bundles with fine-grained reactivity, which suits a UI that updates constantly (tabs, transfer progress, host lists).
React is fine, but you'll carry more runtime and re-render overhead.

UI layer

Tailwind CSS + shadcn-svelte / shadcn/ui (Radix-based) for polished, accessible components.
cmdk-style command palette (Cmd+K) is a must for a "modern" feel.
Icons: Lucide. Panels/splits: paneforge or react-resizable-panels.

Storage and security

SQLite via rusqlite or sqlx for hosts, groups, snippets, history.
Encrypt secrets with age or chacha20poly1305, with a master key derived via Argon2. Store the unlock key in the OS keychain via the keyring crate.
Never store private keys or passwords in plain SQLite.

Sync (optional later)

E2E-encrypted sync: encrypt client-side, then sync blobs via S3/R2, a tiny server, or CRDTs (automerge/yrs) if you want conflict-free merges.

Hopr UI Direction
Pick one identity

Most SSH clients look like "VS Code with a sidebar." To stand out, build the UI around Hopr's core idea: hopping. The path to a server is the star.

Signature ideas (pick 2-3):

Hop trail in the tab bar. Instead of a plain "prod-db" tab, show laptop › bastion › prod-db as a small breadcrumb. Jump-host chains become visible and clickable.
Status as light, not badges. A soft glow or a thin colored edge on a tab or host row (green = live, amber = reconnecting, red = dropped) instead of tiny dots.
Command-bar-first layout. A floating center palette (Ctrl+K) is the main way to move around. The sidebar can collapse to a thin icon rail.
Floating panels, not boxed panes. Terminal fills the window edge to edge. SFTP, tunnels, and snippets slide in as translucent drawers over it and dismiss with Esc.
Host "constellation" view (optional). A graph of hosts and jump relationships as an alternative to the list. It's a lot of work but very memorable.
Design principles
Terminal is the hero. UI chrome should recede: low contrast, thin borders, no heavy toolbars.
Quiet by default, expressive on interaction. Calm resting state, with small motion and glow on hover, focus, and connect.
Density is a setting. Compact, comfortable, and spacious presets that scale spacing tokens.
Keyboard first, mouse friendly. Every action reachable from the palette, with shortcut hints shown inline.
One accent color. Everything else is neutrals. Restraint reads as premium.
Soft geometry. Consistent radius (6-10 px), 1 px hairline borders at about 8% opacity, and layered surfaces rather than shadows.
Motion under 150-200 ms, ease-out, and respect reduced-motion.
Color system

Avoid pure black (#000) and the overused purple-to-blue gradient. Use warm or tinted near-blacks and one distinctive accent.

Scale: 12 / 13 / 14 / 16 / 20 px. Use 13 px as the UI base and tabular numerals for ports, IPs, and transfer speeds.

Icons

Lucide is what every shadcn app uses, so it reads as generic. Better options:

Phosphor Icons is my pick. It has six weights (thin, light, regular, bold, fill, duotone), so icon weight becomes a user setting and instantly gives the UI a different feel.
Tabler has the largest set, which helps for niche concepts like tunnels and keys.
Iconoir and Solar are softer and more stylish.

Draw 5-8 custom signature icons (the Hopr logo, hop/jump, tunnel, vault, and broadcast) in the same stroke style. A small custom set is what makes it feel owned rather than assembled. Keep one stroke width (1.5 px) and sizes at 16 and 20 px.

Architecture Practices
Thin UI, fat core. All SSH, crypto, and file logic lives in Rust. The frontend only renders state and sends intents.
Split the Rust code into crates in a workspace so each part is testable alone:
   hopr/
   ├─ crates/
   │  ├─ hopr-core      # session manager, domain types
   │  ├─ hopr-ssh       # russh wrapper
   │  ├─ hopr-sftp
   │  ├─ hopr-vault     # encryption, keychain
   │  └─ hopr-store     # sqlite, migrations
   ├─ src-tauri/        # thin Tauri glue (commands only)
   └─ src/              # Svelte app
Typed IPC. Generate TypeScript types from Rust (tauri-specta) so a rename in Rust breaks the build in TS instead of at runtime.
Hot path stays binary. Terminal data uses Tauri channels with raw bytes, not JSON events. Batch output every 8-16 ms.
One actor per session. Each connection is a tokio task that owns its state and talks over mpsc channels. This avoids shared-mutex tangles.
Feature modules on the frontend. Group by feature (features/terminal, features/sftp, features/vault) rather than by type (components/, hooks/).
Design tokens only. No hardcoded colors or spacing in components, which is what makes theming and density settings free.
Rust Practices
Prefer types that make invalid states unrepresentable (enums for connection state: Connecting | Authenticating | Ready | Reconnecting | Closed).
Avoid unwrap() and expect() outside tests. Return Result everywhere and map errors to user-friendly messages at the boundary.
Never hold a lock across an .await.
Bounded channels for backpressure (an unbounded queue plus a fast cat bigfile will eat your RAM).
Wrap secrets in secrecy::SecretString and zeroize them on drop. Never log them, and add a test that checks logs don't contain credentials.
Use #![forbid(unsafe_code)] in crates that don't need unsafe.
Use tracing spans per session (session_id, host) so debugging is easy.
TypeScript / Svelte Practices
strict: true, and no any.
Keep components small and presentational. Put logic in plain .ts modules that can be tested without the DOM.
Debounce or throttle UI updates for transfer progress and stats (about 10 fps is plenty).
Virtualize long lists (hosts, SFTP directories, history).
Lazy-load heavy panels (SFTP, settings, graph view).
Respect prefers-reduced-motion and prefers-color-scheme.
Accessibility from the start: focus rings, ARIA roles, and keyboard paths for everything.
Security Practices (critical for an SSH client)
Strict Tauri capabilities and CSP. Allow only the commands and plugins you use, and load no remote content in the webview.
Verify host keys (TOFU with a clear prompt, and a loud warning on change).
Encrypt the vault at rest. Decrypt in memory only when needed.
No telemetry by default, and opt-in only if you add it.
Sign and notarize releases, and sign auto-update payloads.
Pin dependencies with lockfiles, and run cargo-deny and Dependabot or Renovate.
Treat remote output as hostile: sanitize anything rendered outside xterm (titles, file names, MOTDs).
